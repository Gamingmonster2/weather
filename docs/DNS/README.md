# توجيه `weather.com.ly` إلى موقع الأمطار الحالي

هذا الحل مؤقت: نجعل دومين الطقس يعرض **نفس مشروع Rain.ly الذي يعمل الآن** على Cloudflare Pages،
ثم ننتظر أياماً حتى تزول مشكلة المستودع، وبعدها نعود لتطوير المشروع الثاني.

> النتيجة: `weather.com.ly` و `www.weather.com.ly` سيعرضان محتوى Rain.ly نفسه بالضبط
> (نفس التصميم، نفس الخريطة، نفس المقالات) إلى أن تُنشئ مشروع Pages مستقلاً للموقع الثاني.

---

## الطريقة الأولى (الأسهل — موصى بها): من داخل Pages مباشرة

إن كان الدومين `weather.com.ly` مضافاً أصلاً في حساب Cloudflare الخاص بك (DNS فيه)، فلا تحتاج أي ملف:

1. افتح **Cloudflare → Workers & Pages → مشروع Rain.ly** (المشروع الذي يعمل عليه `www.rain.ly`).
2. اذهب إلى تبويب **Custom domains → Set up a custom domain**.
3. اكتب `weather.com.ly` ووافق. Cloudflare سيضيف سجل CNAME المطلوب **تلقائياً** ويصدر شهادة SSL.
4. كرّر الخطوة مع `www.weather.com.ly` إن أردت.
5. احذف السجلات القديمة التي كانت تشير إلى الاستضافة القديمة (Blogger أو غيرها) من
   **DNS → Records** حتى لا يتعارض سجل قديم مع الجديد.
6. انتظر دقائق حتى تظهر الحالة **Active** بجانب الدومين، ثم افتح الرابط.

هذه هي الطريقة المطلوبة فعلياً — الملفات في هذا المجلد احتياطية للحالات الأخرى.

---

## الطريقة الثانية: ملفات DNS جاهزة للرفع / الإدخال اليدوي

أضفت ملفين جاهزين:

| الملف | الاستخدام |
|---|---|
| `weather.com.ly.bind.txt` | صيغة BIND/zone قياسية — ارفعها كملف Zone في معظم مزودي DNS. |
| `weather.com.ly.csv` | جدول بسيط (Type, Name, Value, TTL) — للرفع في واجهات DNS التي تقبل CSV. |

المحتوى الفعلي سجلان فقط:

```
CNAME   weather.com.ly      ->  weather-cs8.pages.dev     TTL 600
CNAME   www.weather.com.ly  ->  weather-cs8.pages.dev     TTL 600
```

### قبل الرفع — تحقق من هدف الـ CNAME

القيمة `weather-cs8.pages.dev` مأخوذة من رابط المعاينة الحالي. تحقق منها:

**Cloudflare → Workers & Pages → مشروع Rain.ly → Domains** — انسخ أي نطاق `*.pages.dev` ظاهر هناك،
واستبدل `weather-cs8.pages.dev` في الملفين إذا كان مختلفاً.

### احذف هذه السجلات القديمة أولاً

من صفحة DNS احذف أي سجلات قديمة للنطاق نفسه:

- سجلات `A` / `AAAA` باسم `weather.com.ly` أو `@`.
- سجل `CNAME` باسم `www` يشير إلى `blogspot.com` أو أي استضافة سابقة.
- أي سجل `CNAME` آخر باسم `weather.com.ly`.

> لا تحذف سجلات `TXT` الخاصة بإثبات ملكية الدومين إلا إذا كان مزوّدك يطلب ذلك صراحةً.

### ملاحظة مهمة عن الـ apex (النطاق بدون www)

بعض مزودي DNS لا يسمحون بـ CNAME على `@`. الحلول بالترتيب:

1. الأفضل: اجعل DNS مستضافاً في Cloudflare — هو يقوم بـ **CNAME flattening** تلقائياً.
2. أو استخدم `ALIAS` / `ANAME` إن كان مزوّدك يدعمه، بنفس القيمة `weather-cs8.pages.dev`.
3. إن لم يتوفر أيّهما، اكتفِ بتوجيه `www.weather.com.ly` فقط الآن.

---

## التحقق بعد التوجيه

```bash
nslookup weather.com.ly
nslookup www.weather.com.ly
```

يجب أن يظهر في النتيجة اسم `pages.dev`. ثم:

- Cloudflare → SSL → Certificates: تأكد أن الشهادة **Active**.
- افتح `https://weather.com.ly` — سترى موقع الأمطار نفسه.
- الانتشار قد يستغرق من دقائق إلى 24–48 ساعة بحسب مزوّد DNS.

## إن أردت تحويلاً حقيقياً (301) بدلاً من عرض نفس المحتوى

قل لي وسأضيف ملف `_redirects` يعيد توجيه `weather.com.ly` إلى `https://www.rain.ly/` بشكل دائم
مع الحفاظ على مسارات المقالات. الافتراضي الآن هو عرض نفس الموقع تحت دومين الطقس كما طلبت.
